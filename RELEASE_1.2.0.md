# v1.2.0 - Configurable Facebook dispatch templates

## Highlights

Version 1.2.0 makes the generated Facebook dispatch message fully configurable without changing the integration source code.

### Custom template file

On first setup, the integration creates:

```text
/config/brandweerrooster/facebook_template.yaml
```

The file contains the same message that was previously generated by the integration, so existing users get the familiar default message.

The integration never overwrites an existing template file.

### Supported placeholders

The following placeholders are available:

- `{kazerne}`
- `{uitrukbericht}`
- `{incident_type}`
- `{melding}`
- `{locatie}`
- `{straat}`
- `{plaats}`
- `{tijd}`
- `{datum}`
- `{prioriteit}`
- `{voertuigen}`
- `{incident_id}`
- `{created_at}`
- `{start_time}`

Users can freely change the wording, order, line breaks, emojis and hashtags in the template.

### Generic station support

The `{kazerne}` placeholder is populated from the configured/incident-related Brandweerrooster station group. The Home Assistant config-entry title is not used for the public station name.

For example:

- `Echt TS` → `Brandweer Echt uitgerukt`
- `Amsterdam TS` → `Brandweer Amsterdam uitgerukt`

No station name is hard-coded in the template engine.

### Backwards-compatible default

If no template file exists, the integration creates the default template automatically. If the file is invalid or empty, the built-in default template is used as a safe fallback and an error is logged.

## Upgrade notes

1. Replace the integration files with version 1.2.0.
2. Restart Home Assistant.
3. On first startup, check `/config/brandweerrooster/facebook_template.yaml`.
4. Edit the file if you want to customize the Facebook message.
5. Restart Home Assistant after changing the template.

No dashboard entity IDs need to change.

## Other functionality

This release does not change:

- FireServiceRota availability/accept/decline handling.
- Event-driven incident processing.
- Personal turnout statistics.
- Incident history persistence.
- P2000 vehicle-code resolution.
- The `Uitrukbericht` entity and its `bericht` attribute.
